# 正文与补充文章写作约束

状态：写作约定与阅读导览已实现。文章页在构建和服务端渲染时自动生成直接补充关系与反向阅读入口；`supplements` 的专项构建校验仍待实现。

适用范围：rbook 的正文与补充文章，以及它们的阅读导览。AI 编写、扩写或拆分文章、实现阅读导览时遵守本文；具体用户指令优先。本文是这类关系的统一规范，写作 prompt 和 skill 通过引用接入，不另行维护一套规则。

## 1. 什么是补充文章

补充文章展开正文中一个明确的问题，读者可以根据需要进入，例如详细证明、深入解释或支线扩展。它与正文的联系必须具体到某个结论、概念或讨论。

“补充”描述文章之间的关系，不表示文件必须属于某个唯一的上级。一篇补充文章可以被多篇正文共享，只维护一份内容；文件放在哪里不决定它能被哪些正文引用。

| 关系 | 用途 | 表达方式 |
| --- | --- | --- |
| 前置知识 | 理解当前文章之前需要掌握的内容 | 当前文章的 `prerequisites` |
| 补充文章 | 展开当前文章的具体问题，供按需深入 | 当前文章的 `supplements`，配合正文就近链接 |
| 普通关联阅读 | 主题相关的其他文章或独立算法章节 | 普通 Markdown 链接 |

不能仅因主题相近就声明补充关系。例如，MST 与严格次小生成树相关，但独立讲解严格次小生成树的章节不因此自动成为 MST 的补充文章。正文也不能把选读的补充证明列成自身的必读前置。

## 2. 正文必须保留什么

- 主算法的正确性必须在正文讲完整，保留必要条件、关键不变量和推理链条。不能把必要论证移走，只留下“证明见另一篇”。
- 应用性质和额外定理可以拆出详细证明，但正文仍需给出结论、适用条件和关键理由，让读者理解为什么可以这样使用。
- 补充文章可以提供更细的推导、示例、直观解释或另一种证明。

例如，MST 正文保留 Kruskal 的完整正确性论证；瓶颈路小节保留性质及关键换边理由，再链接到逐步展开的证明。

## 3. AI 如何决定拆分

不设字数门槛，判断依据是内容是否打断当前教学主线。

- 几句话就能讲清的证明或解释，直接留在正文。
- 围绕一个明确问题，需要多步推导、额外概念或较长示例，而且跳过展开部分仍能继续理解正文时，可以拆出。
- 主算法正确性所必需的论证，即使较长也要留在正文讲完整，不能为了缩短篇幅而外移。

AI 可以对符合条件的内容自主拆分，无需逐篇确认，同时维护元数据和正文链接。拆分前先检查是否已有合适文章，可以复用时不要重复创建。

## 4. 元数据与正文链接

### 正文声明补充文章 ID

使用可选字段 `supplements`，值为文章 ID 的字符串数组：

```yaml
supplements:
  - graph-mst-1
```

- ID 必须来自目标文章的 frontmatter，不能填写路径、URL 或标题。
- 引用的文章必须真实存在且 ID 可唯一定位；不重复列出同一 ID，不引用自身。
- 没有补充文章时省略该字段。
- 初版只使用 ID 列表，不增加类型、说明、标题副本或唯一所属正文字段。标题以目标文章的 `title` 为准。
- 补充文章保留通常的文章元数据，不另设反向所属列表。其他正文需要共享它时，在各自的 `supplements` 中声明同一 ID。

### 在需要的位置给读者入口

每项 `supplements` 声明都应在正文对应内容处有普通 Markdown 链接，不能只在文末集中列出而没有就近入口。按实际用途说明“详细证明见”“进一步解释见”等，不统一把所有补充内容称为证明。

```markdown
详细证明见：[瓶颈路证明](./bottleneck-path-prove.md)。
```

元数据与链接必须指向同一篇文章。补充关系要同时维护两处；普通关联阅读链接不要求进入 `supplements`。

文件改名或移动时，保留稳定 ID，并更新受影响的 Markdown 路径和既有索引配置。确实需要修改 ID 时，同步检查所有引用该 ID 的关系字段。

## 5. 补充文章怎样写

补充文章应让从搜索直接进入的读者也能理解它要解决的问题，不要求重新讲解所有前置知识。

- 开头明确所回答的问题，重述必要的命题、适用条件和符号。
- 提供相关正文的阅读链接，帮助读者补齐背景；共享文章不要假定读者只从某一篇正文进入。
- 随后直接展开证明或解释，避免“上文已经说过”“沿用上面的符号”等依赖另一页面上下文的表达。
- 不套用完整算法教程模板，不为凑结构强行增加算法步骤、代码、复杂度、测试用例或经典例题。仅在确实服务于当前问题时加入这些内容。
- 文章研究、数学准确性、代码存放和图示等现有专项规范仍然适用。

## 6. 目录、搜索与访问

补充文章默认不加入 `book/book.yaml` 的 `chapters`，主要从正文的对应段落进入，但应被索引、可搜索，并能通过链接独立访问。

新增时检查现有 `glob` / `all` 索引机制是否覆盖该文件；不要把“不进主目录”当成“不需要索引”。实际发布前验证搜索和直接访问；遇到现有能力限制时应报告，不要仅凭写了 `supplements` 就声称已实现。

补充文章属于“新增正式教程必须进入主目录”的明确例外，即使引用了代码模板，也不能只凭 `code_template` 将它提升为正式章节。完成文章任务时说明它作为补充文章未加入主目录。

如果内容发展成独立教学专题，可以按正式章节加入目录。主目录收录与文章间的补充关系分别判断，不因加入目录而自动删除仍有意义的引用，也不在采用本规范时批量移除已有目录条目。

## 7. MST 示例

以下是写作示例，不表示现有文章已经修改。

`book/pages/graph/MST/index.md` 的 frontmatter 增加：

```yaml
supplements:
  - graph-mst-1
```

在“瓶颈路问题”的结论附近写明：

```markdown
在无向连通带权图中，对于任意两个不同顶点，任取一棵 MST，其上连接这两点的路径的最大边权，就是原图中这两点所有路径的最大边权的最小值。

关键理由是：删去这条树路径上的一条最大权边，两点会分属两个连通块。如果存在最大边权更小的替代路径，它必然有一条更轻的边跨过这两个连通块；用它替换被删的边，就能得到总权值更小的生成树，与 MST 的最优性矛盾。

详细证明见：[瓶颈路证明](./bottleneck-path-prove.md)。
```

`bottleneck-path-prove.md` 保留现有 ID `graph-mst-1`，开头重述命题和条件，提供背景链接后再展开证明：

```markdown
本文证明：在无向连通带权图中，任意一棵 MST 上连接两个不同顶点的路径，都使路径上的最大边权最小。

算法背景见：[最小生成树](./index.md)。
```

若另一篇正文也需要这份证明，引用同一 ID，按自己的文件位置填写链接即可。

## 8. AI 完成前检查

- 正文完整保留主算法的正确性论证；拆出的应用性质仍有结论、条件和关键理由。
- 补充文章回答具体问题，拆分确实有助于阅读，不是机械按篇幅拆文件。
- `supplements` 是可解析的 YAML 字符串数组，目标 ID 存在、唯一，无重复和自引用。
- 每项声明都有正文就近链接，链接路径存在，并且与所声明 ID 对应。
- 补充文章具备最少上下文和相关正文链接，没有被强套完整教程结构。
- 补充文章默认不进主目录，已检查索引覆盖；实际发布时验证搜索和直接访问。
- 共享内容已复用，文件或 ID 变化的引用已同步。

这些是作者和 AI 的检查责任；当前约定不意味着构建器已经自动执行上述检查。

## 9. 文章开头的阅读导览

本节是阅读导览的展示规范。阅读导览用于让读者快速看清当前文章与补充文章的结构，并选择阅读入口。

### 位置与形式

- 放在文章标题、简介等头部信息之后，正文之前，组件名称为“阅读导览”。
- 使用固定布局的小型关系图，文章节点呈现为简洁的标题卡片；初始布局应直接可读，不需要拖动、缩放或等待力导向布局稳定。
- 当前文章突出显示并标注“正在阅读”；其他文章节点可点击，直接进入对应文章。
- 桌面从左到右排列“引用本文的正文 → 当前文章 → 本文的补充文章”；手机改为从上到下排列，保持相同含义。
- 连接线表达补充关系，不能让读者误以为它表示必读前置或强制阅读顺序。当前页面已有的前置知识入口继续单独表达 `prerequisites`，不混入这张图。

### 只展示当前文章的直接关系

对当前文章 A，展示以下三部分：

| 部分 | 数据来源 | 含义 |
| --- | --- | --- |
| 引用本文的正文 | 所有 `supplements` 包含 A 的已索引文章 | 本文为哪些正文提供补充 |
| 当前文章 | A 的 ID、标题和页面地址 | 读者当前所在的位置 |
| 本文的补充文章 | A 的 `supplements` | 可以从本文继续深入的文章 |

反向关系从其他文章的声明自动推导，不新增反向 frontmatter 字段，也不要求作者手写关系图。关系查询包含未进入主目录的已索引文章，不能只从主目录寻找补充文章。

不递归展开关联正文的其他补充文章，也不展开补充文章的补充文章；不把普通 Markdown 互链自动解释为补充关系。点击另一篇文章后，以新页面的当前文章重新生成直接关系。

例如，假设 MST 正文已声明 `supplements: [graph-mst-1]`，打开《瓶颈路证明》时，导览包含《最小生成树》和《瓶颈路证明》，突出后者。即使《瓶颈路证明》没有自己的 `supplements`，也应显示这条反向关系。另一篇正文若也声明了相同 ID，则共同出现在“引用本文的正文”一组。

### 默认展示与展开

- 默认展开导览，当前文章始终显示。
- “引用本文的正文”和“本文的补充文章”两组独立计数，各默认显示最多 3 篇。
- 某组超过 3 篇时，在该组显示“查看全部 N 篇”，其中 N 为该组文章总数；点击后就地展示该组全部文章，不跳转到其他页面，不递归加载更多层关系。
- 空组省略；两组都为空时，整个组件不显示，也不留下空白占位。
- 无论展开多少文章，手机上标题和链接都应能正常阅读，不依赖横向拖动画布。展开按钮与文章链接应支持键盘操作。

### 与文章写作的关系

作者继续维护 `supplements` 和正文就近链接，节点标题及页面地址由文章索引读取，不另行维护图形数据。页面头部的导览提供整体结构，正文链接提供读到具体结论时的入口，两者同时保留。

阅读导览由共享页面模板在构建和服务端渲染时生成，不依赖浏览器请求文章目录，也不是文章正文中的手写 Mermaid、SVG 或截图。作者不为每篇文章重复画图。

### 实现验收场景

实现和修改组件时，按以下场景验收：

- 没有直接关系：不显示组件。
- 只有自己的补充文章：显示当前文章和对应补充节点。
- 只有其他正文引用自己：仍显示导览，当前补充文章标为“正在阅读”。
- 同时存在两个方向的关系：分组展示，连接含义清楚，不出现邻居的其他关系。
- 同一补充文章由多篇正文共享：在补充文章页列出这些正文，无需添加反向元数据。
- 某组恰有 3 篇：全部展示，无展开按钮；有 4 篇及以上：默认显示 3 篇与正确总数，点击后就地展示全部，另一组不受影响。
- 点击文章节点：进入正确文章，新页面突出新文章并展示它的直接关系。
- 手机布局及展开后的长标题：可读、可点击，键盘能操作链接和展开按钮。
- 原有正文就近链接仍然存在，未因增加导览而被删除。

## 10. 后续工程范围

阅读导览已按第 9 节实现，包括元数据解析、反向关系、节点导航、响应式布局和按组展开。展开使用原生 `details`，无需 JavaScript。

后续工程范围：构建时校验字段类型、目标 ID 与正文链接的一致性。

无论这些功能是否已经实现，都保留明确的正文 Markdown 链接作为就近阅读入口。
