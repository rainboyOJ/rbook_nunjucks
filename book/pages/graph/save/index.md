## 一句话算法

存图先用“列表套列表”的邻接表；只有要给边发一个稳定编号时，才用链式前向星把边串成链。

## 问题模型

图论题通常需要频繁遍历某个点的所有出边。我们需要一种存图方式，支持：

- 加一条有向边或无向边；
- 枚举从点 $u$ 出发的所有边；
- （部分算法额外要求）通过边编号找到反向边、给某条边打标记。

设点数为 $n$，边数为 $m$，$d^+(u)$ 表示点 $u$ 的出度。目标是加边 $O(1)$、枚举 $u$ 的出边 $O(d^+(u))$、空间 $O(n+m)$。

邻接矩阵要开 $n^2$ 的表，稀疏图浪费严重；直接存边（开一个边表逐条扫）枚举出边要 $O(m)$。所以大多数图用**邻接表**：每个点挂一个列表，正好满足前两条要求。只有当算法还要第三条——边有稳定编号——时，才升级到**链式前向星**。

| 算法还需要什么 | 选择 |
|---|---|
| 只加边、枚举出边（DFS/BFS/最短路/拓扑） | 邻接表 |
| 边的稳定编号（网络流 $i \oplus 1$ 反向边、给边打标记） | 链式前向星 |
| $O(1)$ 查询 $u \to v$ 是否存在，且点数不大 | 邻接矩阵 |
| 把边按权值排序整体处理（Kruskal） | 直接存边（边表） |

## 核心直觉

### 邻接表：一个点一个列表

$g[u]$ 就是点 $u$ 的出边列表：加边就往列表里 `append`，遍历就用 `for`。没有指针、没有链表，列表本身负责扩容。

顶点编号是 $0 \ldots n-1$ 时用列表套列表：

```python
g = [[] for _ in range(n)]
```

顶点编号稀疏或不连续时，把外层换成 `defaultdict(list)` 即可，遍历写法不变。

### 链式前向星：出边串成链

把每个点的出边看成一条链：

```text
head[u] -> edge i -> edge next[i] -> edge next[next[i]] -> 空
```

新增边 $(u,v,w)$ 时，把它插到 $u$ 的链表头：

```text
edge[cnt].next = head[u]
head[u] = cnt
cnt++
```

这样加边是 $O(1)$，遍历 $u$ 的所有出边时沿着 `next` 走即可。每条边在边表里有固定下标，这个下标就是边的编号。

## 算法步骤

### 邻接表

1. 建 $n$ 个空列表（或一个 `defaultdict(list)`）。
2. 加有向边 $(u,v,w)$ 就 `g[u].append((v, w))`；无向边在两个方向各 append 一次。
3. 遍历 $u$ 的出边就是 `for v, w in g[u]`。

### 链式前向星

1. 初始化所有 $head[u]$ 为空，表示没有出边。
2. 新增边时，把边的信息写入边表末尾，新边的编号就是它在边表里的下标。
3. 令新边的 `next` 指向原来的 $head[u]$。
4. 更新 $head[u]$ 为新边的编号。
5. 遍历点 $u$ 时，从 $head[u]$ 开始不断跳 `next`。

## 算法证明

邻接表没有需要证明的不变量：列表里第 $i$ 个元素就是第 $i$ 条加入的边，`append` 与 `for` 的语义由语言本身保证。

链式前向星需要证明“遍历链表恰好枚举 $u$ 的所有出边”。

**核心不变量**：$head[u]$ 始终指向点 $u$ 最近加入的一条出边，`next` 串起之前所有从 $u$ 出发的边。

1. 初始化时 $head[u]$ 为空，每个点的出边链为空。
2. 加入新边时，新边的 `next` 指向原链表头，所以旧边没有丢失。
3. 再令 $head[u]$ 指向新边，所以新边成为链表头。
4. 其他点的 $head$ 不变，因此只改变了点 $u$ 的出边链。

所以每条加入的边都会且只会被挂到它起点的链表中，遍历链表即可枚举所有出边。

## 复杂度分析

设点数为 $n$，边数为 $m$，$d^+(u)$ 为点 $u$ 的出度。

| 操作 | 邻接表 | 链式前向星 | 邻接矩阵 |
|---|---|---|---|
| 加一条边 | $O(1)$ | $O(1)$ | $O(1)$ |
| 枚举 $u$ 的出边 | $O(d^+(u))$ | $O(d^+(u))$ | $O(n)$ |
| 查询 $u \to v$ 是否存在 | $O(d^+(u))$ | $O(d^+(u))$ | $O(1)$ |
| 遍历整张图 | $O(n+m)$ | $O(n+m)$ | $O(n^2)$ |
| 空间 | $O(n+m)$ | $O(n+m)$ | $O(n^2)$ |

- 建图时间复杂度：$O(m)$（邻接表与链式前向星相同）。
- 遍历整张图的时间复杂度：$O(n+m)$。
- 空间复杂度：$O(n+m)$。

邻接表与链式前向星的渐进复杂度完全一样。差别在常数与能力：邻接表写法短、遍历快；链式前向星换来的是“每条边有编号”。C++ 中两者常数接近，怎么写都行；Python 中列表套列表通常更快也更短，所以 Python 只在必须用边编号时才写链式前向星。

## 代码实现

### 邻接表

C++ 的邻接表写法很短，直接写在正文里：

```cpp
// 顶点 0..n-1 的邻接表，带权存 (v, w)；无权用 vector<int> g[maxn] 即可
vector<pair<int, int>> g[maxn];

void add(int u, int v, int w) {
    g[u].push_back({v, w});  // 无向边就再加一行 g[v].push_back({u, w});
}
```

## 测试用例

输入边：

```text
1 2 5
1 3 7
2 4 9
```

**邻接表**：`g[1].append((2, 5))`、`g[1].append((3, 7))`、`g[2].append((4, 9))` 后，遍历点 $1$ 的出边得到 $1 \to 2$ 和 $1 \to 3$，顺序与加边顺序相同。

**链式前向星**：如果用 `add(1,2,5)`、`add(1,3,7)`、`add(2,4,9)` 建图，遍历点 $1$ 的出边得到 $1 \to 3$ 和 $1 \to 2$。由于使用头插法，遍历顺序与加边顺序相反。

!!! warning 顺序差异
邻接表按加边顺序返回出边，链式前向星按加边的倒序返回。只依赖“枚举全部出边”的算法不受影响；依赖输入顺序逐条处理邻边的算法要注意这个差别。
!!!

## 应用分类详解

存图的本质是“让算法高效枚举某点的出边”。选哪种存储，看算法除了枚举出边还需要什么。

### 一、只需要枚举出边（日常首选邻接表）

**典型模式：** DFS、BFS、拓扑排序、最短路、生成树、二分图匹配。

**识别信号：** 题面给一张边表，算法只需要“访问 $u$ 的每个邻居”。

**核心建模：** 每个点挂一个列表，加边 append，遍历 for。

| 应用场景 | 经典题目 | 核心思路 |
|---|---|---|
| 图遍历 | 本书图遍历章节 | 枚举出边继续 DFS/BFS |
| 拓扑排序 | 本书拓扑排序章节 | 删除点时枚举出边更新入度 |
| 单源最短路 | [[problem: luogu,P3371]] | 每次取出 $u$ 后枚举出边松弛 |

### 二、需要边的稳定编号（链式前向星）

**典型模式：** 网络流、割边、欧拉路径、重边标记。

**识别信号：** 出现网络流、割边、欧拉路径等算法；需要随时找到“这条边的反向边”或给某条边打标记。

**核心建模：** 每条边有稳定编号，成对加边时可以用 $i \oplus 1$ 找配对反向边。

| 应用场景 | 经典题目 | 核心思路 |
|---|---|---|
| 最大流 | [[problem: luogu,P3376]] | 正反边成对存储 |
| 割边 | 本书割边章节 | 用进入边编号避免重边误判 |

### 三、需要 $O(1)$ 查边（邻接矩阵）

**典型模式：** 传递闭包、Floyd、点数不大的稠密图。

**识别信号：** $n^2$ 的空间可以接受，且频繁查询“$u$ 到 $v$ 有没有边”。

**核心建模：** 二维表 $adj[u][v]$ 直接存边的有无或权值。

| 应用场景 | 经典题目 | 核心思路 |
|---|---|---|
| 传递闭包 | 本书 Floyd 章节 | 布尔矩阵自乘 |
| 判两点直连 | 小规模稠密图 | $O(1)$ 查询 |

## 经典例题

### 1. [[problem: luogu,P3371]]

单源最短路模板题。稀疏图用邻接表存边即可；算法只需要枚举出边，不必用链式前向星。

### 2. [[problem: luogu,P3386]]

二分图匹配。每次 DFS 从左部点枚举所有可连的右部点，邻接表存图。

### 3. [[problem: luogu,P3376]]

最大流模板。需要正向边和反向边成对存储、用编号互相定位，链式前向星很适合这种写法。
