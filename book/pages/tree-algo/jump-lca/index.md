## 一句话算法

倍增 LCA 先让深的点向上跳到同一层，再让两个点一起从大步到小步向上跳。

## 问题模型

给定一棵有根树，需要多次查询两个点 $u$ 和 $v$ 的最近公共祖先。

树必须先选定根。根不同，祖先关系也可能不同，所以如果题目给出了根节点 $s$，预处理时就应该从 $s$ 开始 DFS；只有题目没有指定根时，才通常把 $1$ 当作根。

!!! definition 最近公共祖先
在一棵有根树中，$u$ 和 $v$ 的公共祖先里，深度最大的那个节点叫做它们的最近公共祖先，记作 $\text{lca}(u, v)$。
!!!

常见扩展查询：

- 两点距离：$\text{depth}[u] + \text{depth}[v] - 2 \times \text{depth}[\text{lca}(u, v)]$。
- 判断祖先关系。
- 树上路径拆分。
- 树上差分。

## 核心直觉

如果一个点比另一个点深，两个点不在同一层，就不能直接比较祖先。

第一步先把深的点往上提到同一深度。为了不一步一步跳，我们预处理：

$$
\text{up}[u][j] = u \text{ 的 } 2^j \text{ 级祖先}
$$

这样任意距离都可以拆成若干个二进制位。例如要上跳 $13$ 层：

$$
13 = 8 + 4 + 1
$$

就依次跳 $2^3$、$2^2$、$2^0$。

## 算法步骤

### 预处理

任选一个根节点，一般取 $1$；如果题目给出根节点，就使用题目给出的根。

DFS 整棵树，求出：

- $\text{depth}[u]$：节点 $u$ 的深度。
- $\text{up}[u][0]$：节点 $u$ 的父亲。
- $\text{up}[u][j]$：节点 $u$ 的 $2^j$ 级祖先。
- DFS 序的进入时间和离开时间：如果需要 $O(1)$ 判断祖先关系，可以额外维护 `in[u]` 和 `out[u]`。

倍增表的层数 `LOG` 要满足 $2^{\text{LOG}} > n$。如果写成固定常量，需要保证它覆盖题目的最大 $n$；如果题目规模变化大，更稳妥的做法是在程序里按 $n$ 计算。

转移式：

$$
\text{up}[u][j] = \text{up}[\text{up}[u][j-1]][j-1]
$$

直觉是：$2^j$ 级祖先 = 先跳 $2^{j-1}$，再从那个位置继续跳 $2^{j-1}$。

![树上从 u 向上跳到各级祖先，并对应填写 up[u][j] 祖先表。](/tree-algo/jump-lca/images/lca-up-table.svg)

### 第 k 祖先

倍增表不仅能求 LCA，也能回答“节点 $u$ 的第 $k$ 级祖先是谁”。

把 $k$ 拆成二进制位，从低位到高位检查：

```cpp
for (int j = 0; j < LOG; ++j) {
    if (k & (1 << j)) u = up[u][j];
}
```

例如 $k = 13$，因为 $13 = 8 + 4 + 1$，所以依次跳 $2^3$、$2^2$、$2^0$。这个操作正是查询 LCA 时“把深点提到同一深度”的基础。

### 查询 LCA

查询 $\text{lca}(a, b)$：

1. 如果 $a$ 比 $b$ 浅，交换它们，保证 $a$ 更深。
2. 让 $a$ 上跳 $\text{depth}[a] - \text{depth}[b]$ 层，使两点同深。
3. 如果此时 $a = b$，说明浅点就是 LCA。
4. 从大到小枚举 $j$：
   - 如果 $\text{up}[a][j] \neq \text{up}[b][j]$，说明还没跳过 LCA，可以同时上跳。
   - 如果相同，说明这一步会跳到 LCA 或 LCA 之上，暂时不能跳。
5. 循环结束时，$a$ 和 $b$ 停在 LCA 的两个不同儿子子树中，答案是 $\text{up}[a][0]$。

![两个节点从不同分支同时上跳，下一跳会汇合到 LCA，因此停止。](/tree-algo/jump-lca/images/lca-simultaneous-jump.svg)

### 祖先关系判断

判断 $u$ 是否为 $v$ 的祖先，常见有两种写法。

第一种直接用 LCA：

$$
u \text{ 是 } v \text{ 的祖先} \Longleftrightarrow \text{lca}(u, v) = u
$$

第二种用 DFS 序。预处理进入时间 `in[u]` 和离开时间 `out[u]` 后：

```cpp
bool is_ancestor(int u, int v) {
    return in[u] <= in[v] && out[v] <= out[u];
}
```

如果文章只需要基础 LCA，第一种足够；如果后续还要做子树判断、虚树或路径包含判断，第二种更方便。

## 算法证明

### 一、同深不丢答案

假设 $a$ 更深。

LCA 一定是 $a$ 的祖先，也是 $b$ 的祖先，所以 $a$ 到 LCA 的路径长度不少于 $b$ 到 LCA 的路径长度。先把 $a$ 上跳到和 $b$ 同深，只会删除 $a$ 到 LCA 下方的那段路径，不会跳过 LCA。

因此同深后，LCA 仍然是两个点的公共祖先。

### 二、从大到小同时跳是正确的

同深后，如果 $a \neq b$，它们分别在 LCA 的不同分支里。

从大到小枚举 $j$ 时：

- 如果 $\text{up}[a][j] \neq \text{up}[b][j]$，两者跳完仍在 LCA 下方的不同分支，可以安全跳。
- 如果 $\text{up}[a][j] = \text{up}[b][j]$，这次跳会把它们汇合到同一个祖先，可能已经到达或越过 LCA，所以不能跳。

循环结束后，已经不能再让两个点保持“不同祖先”地向上跳。此时它们正好在 LCA 的下面一层，所以父亲就是 LCA。

## 复杂度分析

设树有 $n$ 个节点。

- 预处理时间复杂度：$O(n \log n)$。
- 单次查询时间复杂度：$O(\log n)$。
- 空间复杂度：$O(n \log n)$。

如果额外维护 DFS 序，预处理时间仍是 $O(n \log n)$，空间只多出 $O(n)$。

## 扩展：路径信息一起倍增

很多题不只问 LCA，还会问路径上的最大边、最小边、边权和等信息。这时可以在 `up[u][j]` 旁边再维护一个同样大小的表。

例如维护从 $u$ 向上跳 $2^j$ 条边经过的最大边权：

$$
\text{mx}[u][j] = \max(\text{mx}[u][j-1], \text{mx}[\text{up}[u][j-1]][j-1])
$$

它的含义和 `up` 表完全一样：一段长度 $2^j$ 的路径，被拆成两段长度 $2^{j-1}$ 的路径。

查询两点路径信息时，仍然先把深点提到同深，再同时上跳；每一次跳跃时，把对应的路径信息合并进答案即可。

常见扩展：

| 维护信息 | 表示含义 | 典型用途 |
|---|---|---|
| `mx[u][j]` | 向上跳 $2^j$ 条边的最大边权 | 严格次小生成树、瓶颈路 |
| `mn[u][j]` | 向上跳 $2^j$ 条边的最小边权 | 路径瓶颈最小值 |
| `sum[u][j]` | 向上跳 $2^j$ 条边的边权和 | 树上路径长度或费用 |

!!! warning 扩展时的边界
如果维护的是边权，节点跳到 LCA 时不要把 LCA 的父边算进去。通常只在实际发生上跳时合并这段跳跃对应的信息。
!!!

## 测试用例

树结构：

```text
        1
      /   \
     2     3
    / \   / \
   4   5 6   7
```

查询结果：

| 查询 | LCA | 说明 |
|---|---|---|
| $\text{lca}(4, 5)$ | $2$ | 同在 $2$ 的子树 |
| $\text{lca}(4, 6)$ | $1$ | 分别在根的左右子树 |
| $\text{lca}(3, 7)$ | $3$ | 一个点是另一个点的祖先 |
| $\text{dist}(4, 6)$ | $4$ | 路径是 $4 \to 2 \to 1 \to 3 \to 6$ |

## 应用分类详解

LCA 的本质是把树上两点路径拆成“向上到公共祖先”的两段。

### 一、树上路径查询

**典型模式：** 题目反复询问两点路径上的长度、权值和、最大值或最小值。

**识别信号：** 多次询问 $u$ 到 $v$ 的路径，路径经过它们的公共祖先。

**核心建模：** 先找到 $\text{lca}(u, v)$，再把路径拆成 $u \to \text{lca}$ 和 $v \to \text{lca}$。

| 应用场景 | 经典题目 | 核心思路 |
|---|---|---|
| 两点距离 | [[problem: luogu,P3379]] | 距离由两点深度和 LCA 深度计算 |
| 路径最大边 | 次小生成树类问题 | 倍增表中同时维护祖先和路径信息 |

### 二、祖先关系判断

**典型模式：** 判断一个点是否在另一个点的子树里，或某个点是否位于路径上。

**识别信号：** 祖先、后代、子树、路径经过。

**核心建模：** 用 LCA 或 DFS 序判断包含关系。

| 应用场景 | 经典题目 | 核心思路 |
|---|---|---|
| 判断祖先 | DFS 序 + LCA | $\text{lca}(u, v) = u$ 表示 $u$ 是 $v$ 的祖先 |
| 路径包含 | 距离拆分 | $\text{dist}(a, x) + \text{dist}(x, b) = \text{dist}(a, b)$ |

### 三、树上差分

**典型模式：** 多次给树上路径加一，最后统计点或边的贡献。

**识别信号：** 多条路径、路径覆盖次数、最后统一统计。

**核心建模：** 对路径两端加贡献，在 LCA 和 LCA 的父亲处抵消，然后 DFS 汇总。

| 应用场景 | 经典题目 | 核心思路 |
|---|---|---|
| 点差分 | [[problem: luogu,P3258]] | $u$、$v$ 加，$\text{lca}$ 和 $\text{fa}[\text{lca}]$ 减 |
| 边差分 | 树上路径覆盖 | $u$、$v$ 加，$\text{lca}$ 减两次 |

### 四、第 k 祖先与向上跳跃

**典型模式：** 询问某个点向上走 $k$ 步后到达哪里，或模拟很多次向父亲移动。

**识别信号：** 第 $k$ 个祖先、向上跳 $k$ 层、父亲指针、撤销到某个历史状态。

**核心建模：** 把 $k$ 拆成二进制，用 `up[u][j]` 一次跳 $2^j$ 步。

| 应用场景 | 经典题目 | 核心思路 |
|---|---|---|
| 第 k 祖先 | [[problem: luogu,P5903]] | 预处理祖先表后按二进制位跳 |
| 历史状态跳转 | 撤销类树形结构 | 把操作形成一棵树，在树上找祖先 |

### 五、路径信息维护

**典型模式：** 多次询问树上两点路径的最大边、最小边、边权和或瓶颈值。

**识别信号：** 树上路径、边权最大值、瓶颈、替换一条边、次小生成树。

**核心建模：** LCA 负责把路径拆成两段；倍增表在跳跃时同步合并路径信息。

| 应用场景 | 经典题目 | 核心思路 |
|---|---|---|
| 路径最大边 | [[problem: luogu,P1967]] | 跳祖先时维护最大边权 |
| 严格次小生成树 | [[problem: luogu,P4180]] | 非树边加回后查询环上的最大/次大边 |

## 方法对比

LCA 有多种求法，倍增不是唯一方法，但它最适合当作竞赛里的通用模板。

| 方法 | 预处理 | 单次查询 | 适合场景 |
|---|---|---|---|
| 倍增 LCA | $O(n \log n)$ | $O(\log n)$ | 在线查询、容易扩展路径信息 |
| 欧拉序 + RMQ | $O(n \log n)$ | $O(1)$ | 静态树、只问 LCA |
| Tarjan 离线 LCA | 近似线性 | 离线统一处理 | 所有询问提前给出 |
| 树链剖分 | $O(n)$ | $O(\log n)$ | 同时做路径修改和路径查询 |

如果题目只问 LCA，倍增写法已经足够稳定；如果题目还要路径加、路径和、路径最大值等复合操作，再考虑树链剖分或在倍增表里维护额外信息。

## 易错点

- `LOG` 不够大：必须保证 $2^{\text{LOG}} > n$。
- 根节点用错：题目给根时，预处理要从题目给定的根开始。
- 忘记处理祖先关系：同深后如果 $a = b$，应立即返回。
- 根的父亲处理不一致：常见做法是令根的父亲为 `0` 或根自己，但整份代码要统一。
- 递归 DFS 爆栈：当 $n$ 很大且树退化成链时，递归深度可能达到 $n$。
- 带权扩展多算边：路径信息只在实际上跳时合并，不要把 LCA 上方的边算进答案。
