## 一句话算法

快读“跳空白、判负号、十倍累加”，快写“先判负、除十递、取模转字符”。

## 问题模型

在算法竞赛中，输入输出（I/O）往往是程序效率的隐形瓶颈。当输入输出的数据规模达到 $10^5 \sim 10^7$ 级别时，耗时往往不在于算法本身的计算，而在于将外部文本流解析为内存数值的过程。

### 为什么标准 I/O 较慢

以 C++ 为例，常见 I/O 方式的开销主要集中在以下三个层面：

1. **流同步机制**：`std::cin` 与 `std::cout` 默认与 C 语言标准 I/O（`scanf`/`printf`）共享缓冲区以保证兼容性，这种同步机制会增加额外的虚函数调用与状态维护开销。
2. **输入输出流绑定**：默认情况下 `std::cin` 绑定到 `std::cout`，每次执行读取操作前都会隐式调用 `std::cout.flush()`，在大规模交互读写时导致频繁刷新。
3. **格式化与本地化解析**：`scanf` 和 `printf` 需要在运行时解析格式化字符串（如 `%d`、`%lld`），根据本地化规则处理字符编码，并进行动态类型检查，这些对于纯十进制整数读写来说是多余开销。

### 目标

使用最精简的底层字符输入输出函数（`getchar` 和 `putchar`），绕过所有格式化解析与缓冲同步，提供一套类型自适应、无外部状态依赖、可在 1 分钟内手工默写的快速 I/O 模板。

## 核心直觉

一个十进制整数在文本流中以字符序列的形式呈现，例如字符串 `"-4028"`。

### 1. 读入直觉：秦九韶算法（高位到低位）

字符从左往右依次到达。忽略正负号后，数值构建过程与多项式求值完全一致：

$$
4028 = ((4 \times 10 + 0) \times 10 + 2) \times 10 + 8
$$

因此，读入只需要做两件事：
1. 不断读取字符，直到遇到第一个数字字符；在此过程中如果遇到负号 `'-'`，就记录符号标志 $f = -1$。
2. 一旦进入数字区间，每读取一位字符 $ch$，就让已有结果乘以 $10$ 并加上 $(ch - \text{'0'})$，直到遇到下一个非数字字符（空格、换行或文件末尾）。

### 2. 输出直觉：递归调用栈（低位到高位转高位到低位）

对整数 $x$ 取模 $x \bmod 10$ 能剥离出最低位，除以 $10$ 可以移去最低位。但是字符输出流要求**必须先输出高位、后输出低位**。

常规方法需要开辟一个数组作为临时栈，将剥离出的各位压栈，再倒序弹出输出。然而，函数本身的调用栈就是最天然的后进先出（LIFO）结构：

- 先递归处理高位：`write(x / 10)`
- 递归返回时输出当前最低位：`putchar(x % 10 + '0')`

当递归到 $x \leqslant 9$ 时，满足基准条件直接输出最高位，然后层层返回依次输出后续低位。这种结构无需定义外部数组，无需维护指针，甚至能自动处理 $x = 0$ 的情况，代码仅有三行，心智负担几乎为零。

## 算法步骤

### 快读步骤 (`read`)

1. 初始化累加变量 $x = 0$，符号因子 $f = 1$。
2. 读取首个字符 $ch = \text{getchar}()$。
3. 循环判断：若 $ch < \text{'0'}$ 或 $ch > \text{'9'}$，判断是否为负号；若是负号则设 $f = -1$；继续读取下一个字符。
4. 循环判断：若 $ch \geqslant \text{'0'}$ 且 $ch \leqslant \text{'9'}$，更新 $x = x \times 10 + (ch - \text{'0'})$，继续读取下一个字符。
5. 将结果赋为 $x \times f$ 并完成赋值。

### 快写步骤 (`write`)

1. 若 $x < 0$，输出字符 `'-'`，并将 $x$ 置为其相反数 $-x$。
2. 若 $x > 9$，说明存在更高位，递归调用自身：`write(x / 10)`。
3. 输出当前个位对应的 ASCII 字符：`putchar(x % 10 + '0')`。

## 算法证明

### 1. 读入正确性

设输入的一串数字字符为 $c_k, c_{k-1}, \dots, c_0$，其中 $c_i \in \{0, 1, \dots, 9\}$。

在循环开始前，$x_0 = 0$。第 $m$ 次循环更新规则为：

$$
x_m = x_{m-1} \cdot 10 + c_{k-m+1}
$$

经数学归纳可知：

$$
x_k = \sum_{i=0}^k c_i \cdot 10^i
$$

乘上符号因子 $f$ 后，结果严格等于文本流所表示的十进制整数。

### 2. 递归输出正确性与终止性

**终止性**：每次递归调用入参为 $\lfloor x / 10 \rfloor$。对于任意整数 $x \geqslant 10$，显然有 $\lfloor x / 10 \rfloor < x$。状态单调严格递减，至多经过 $\lfloor \log_{10} x \rfloor$ 次调用必达到基准状态 $x \in [0, 9]$，递归必在有限步内终止。

**输出顺序**：
- 对于 $x \in [0, 9]$，直接执行 `putchar(x + '0')`，正确输出。
- 对于 $x \geqslant 10$，由归纳假设，`write(x / 10)` 率先正确输出除个位外的所有前缀高位。待该子任务全部输出完毕后，程序执行下一行 `putchar(x % 10 + '0')`，精准拼接上最后一位。因此输出顺序与十进制表示完全一致。

**栈深度安全性**：对于 64 位有符号整型 `long long`，最大值约为 $9.22 \times 10^{18}$，十进制位数不超过 $19$。最大递归深度至多为 $19$ 层，函数调用开销微乎其微，绝不会导致栈溢出。

## 复杂度分析

- **时间复杂度**：
  - 单个数值读入与输出的时间复杂度均为 $O(\log_{10} |x|)$，即与该数值的十进制位数呈线性关系。对于固定位宽的整型（`int`、`long long`），可以视为常数时间 $O(1)$。
  - 读取或输出 $N$ 个整数的总耗时为 $O(N \cdot L)$，其中 $L$ 为平均十进制位数，达到理论最优的字符流处理下界。
- **空间复杂度**：
  - 读入操作仅使用固定辅助变量，额外空间复杂度为 $O(1)$。
  - 递归输出的系统调用栈深度为 $O(\log_{10} |x|) \leqslant 19$，额外空间复杂度为 $O(\log_{10} |x|)$，属于微小常量级开销。

## 测试用例

### 用例一：一般混合情况（正负数与多空格）

**输入：**
```text
5
10   -2
3 0 -5
```

**输出：**
```text
10 8 11 11 6
```

**过程分析：**
1. 读入 $n = 5$。
2. 依次读取各个数值，中间的连续空格与换行被前导循环自动过滤。
3. 负数正确捕获符号因子，`0` 正确保留。
4. 前缀和依次为 $10$、$10 + (-2) = 8$、$8 + 3 = 11$、$11 + 0 = 11$、$11 + (-5) = 6$。

### 用例二：单元素为 0

**输入：**
```text
1
0
```

**输出：**
```text
0
```

**过程分析：**
- 读入阶段：`ch = '0'` 直接进入数字读取循环，$x = 0$，$0 \times 1 = 0$。
- 输出阶段：$x = 0$，不满足 $x < 0$ 与 $x > 9$，直接输出 `0 + '0' = '0'`。完美处理了边界零值。

## 应用分类详解

快速 I/O 的应用本质是：**根据题目给定的数据规模与时间限制，选择性价比最高、心智负担适宜的输入输出优化方案**。

```
数据吞吐量选择阶梯:
  N <= 10^4              -> 默认 std::cin / std::cout 或 scanf / printf
  10^4 < N <= 10^5       -> 关闭流同步: ios::sync_with_stdio(0); cin.tie(0);
  10^5 < N <= 10^6       -> 竞赛极简快读快写 (getchar / putchar)
  N > 10^6 (极端卡常题)   -> 块缓冲快读快写 (fread / fwrite)
```

### 一、基础阶梯：标准流解绑

**典型模式：** 数据量 $N \leqslant 10^5$，题目时限较为充裕（如 1.0s），题面没有极度严苛的卡常标记。  
**识别信号：** 常规图论、动态规划、字符串题目。  
**核心建模：** 在 `main()` 函数开头直接解绑流同步与关联，继续书写熟悉的 `cin >> x` 与 `cout << x << '\n'`。

```cpp
std::ios::sync_with_stdio(false);
std::cin.tie(nullptr);
```

### 二、竞赛首选：字符级极简快读快写（本模板）

**典型模式：** 输入规模 $N \in [10^5, 2 \times 10^6]$，或者涉及频繁询问（如树状数组、线段树、ST 表、莫队算法等）。  
**识别信号：**
1. 题目包含大规模数组输入，如数论筛法打表查询、树上多组点对查询。
2. 纯整数读入量极大，提交时偶发接近时限的超时（TLE）。  
**核心建模：** 默写 15 行内的 `read` 和 3 行递归 `write`，使用一条语句批量读入，将 I/O 耗时压减至原先的 $1/3 \sim 1/5$。

| 应用场景 | 典型特征 | 优势 |
|---|---|---|
| ST 稀疏表高频查询 | $10^5$ 规模数组，$10^6$ 次区间极值询问 | 避免每一次查询输出被格式化拖垮 |
| 树状数组 / 线段树 | 高频修改与查询指令混合输入 | 连续读入数字不卡常 |
| 图论建图输入 | $M \geqslant 10^6$ 条边读入 | 大幅缩短建图前置耗时 |

### 三、极限阶梯：块缓冲 I/O（`fread` / `fwrite`）

**典型模式：** 极端数据量 $N \geqslant 5 \times 10^6$ 甚至达到几千万字节（几百 MB）的特殊卡常题或大厂压测赛题。  
**识别信号：** 题面特别注明“本题输入量巨大，请使用极速读入”，时限卡在 0.2s ~ 0.5s 极限边缘。  
**核心建模：** 开辟 $1 \sim 4\text{ MB}$ 的大数组，通过系统调用 `fread` 一次性整块加载，指针内部滑动自增。因为该方案代码繁冗、调试时容易吞字符且不易默写，仅在常规快读无法通过时作为秘密武器使用。

## 经典例题

### 1. 洛谷 P1001 A+B Problem

- **链接**：[Luogu P1001](https://www.luogu.com.cn/problem/P1001)
- **题目简述**：输入两个整数 $A$ 和 $B$（可能为负数），输出它们的和。
- **练习重点**：
  - 检验快读对**负数**的处理是否正确（验证符号标记因子 $f$）。
  - 检验快写对负数结果是否正确输出负号。
  - 是测试新写模板最轻便的沙盒题目。

### 2. 洛谷 P3865 【模板】ST 表

- **链接**：[Luogu P3865](https://www.luogu.com.cn/problem/P3865)
- **题目简述**：给定 $N \leqslant 10^5$ 个数的序列，进行 $M \leqslant 2 \times 10^6$ 次静态区间最大值查询。
- **重点分析**：
  - 本题是经典的“计算只需 $O(1)$，瓶颈全在 I/O”的典型案例。
  - $M = 2 \times 10^6$ 次询问意味着输出量高达两百万行。直接使用 `std::cout << ans << std::endl` 会严重超时；即使关闭同步，流输出开销依然显著。
  - 使用本章的递归快写 `write(ans); putchar('\n');` 能轻松跑进题目时间限制的一半以内。

### 3. 洛谷 P1908 逆序对

- **链接**：[Luogu P1908](https://www.luogu.com.cn/problem/P1908)
- **题目简述**：给定长度为 $N \leqslant 5 \times 10^5$ 的数组，求序列中逆序对的总数。
- **重点分析**：
  - 逆序对总数最大可达到 $\frac{N(N-1)}{2} \approx 1.25 \times 10^{11}$，必须使用 `long long` 保存结果。
  - 本题能直接检验快读泛型模板 `read(n)` 以及递归快写 `write(ans)` 对 `long long` 类型的天然无缝支持。

## 避坑指南与技巧

!!! warning 严禁混用标准流与 C 字符接口
如果在程序开头执行了 `std::ios::sync_with_stdio(false)`，**绝对不能**在后续代码中将 `std::cin / std::cout` 与 `getchar / putchar / scanf / printf` 混合使用。关闭同步后，C++ 流与 C 缓冲池完全脱钩，混用会导致输入乱序、字符遗失或不可预知的未定义行为。
!!!

!!! warning 别忘了输出分隔符
本模板的 `write(x)` 函数**只负责打印数字本身**，不会自动附加空格或换行符。需要多数字同行或换行展示时，请使用 `write(x, ' ')`、`write(x, '\n')` 或 `writeln(x)`。
!!!

!!! tip 极端边界：最小值取相反数
对于有符号整型，负数绝对值比正数多 1（例如 32 位有符号整型的范围为 $[-2^{31}, 2^{31}-1]$）。在极端情况下，如果输入恰好是最小值（如 `INT_MIN`），执行 `x = -x` 会发生有符号整型溢出。在普通算法竞赛中极少有数据正好卡在这一单点；若遇此极端测试点，只需将变量类型扩展为 `long long` 或改用无符号类型接收即可。
!!!
