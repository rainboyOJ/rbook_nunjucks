# RBook 参考资料研究 Skill

这个 skill 只负责参考资料研究，不负责决定 rbook 的文章结构、代码放置或导航。配合文章写作时，与 `rbook-article-writer` 同时使用；单独调用时，输出一份可核验的资料研究报告。

## 资料源

每次研究开始前，完整读取 `references/source-catalog.md`。它是四个本地资料源的唯一清单，集中维护路径、正文格式、主要用途、许可证和特殊入口。

每次都检索清单中的四个当前内容入口，但只读取与目标主题直接相关的文件。资料仓库保持只读；某个入口不存在或不可读时记录具体路径并继续其余来源。四个来源都不可用时也可以继续任务，但必须明确报告外部研究未完成。

## 检索流程

1. 确定研究目标。
   - 记录算法名、问题模型、目标文章路径和本次要补强的内容。
   - 配合文章任务时，以目标 `index.md` 或目标 Markdown 所在目录作为文章目录；文章还不存在时使用计划创建它的目录。
   - 单独研究且没有目标文章目录时，不自动创建目录或记录文件。

2. 生成检索词。
   - 同时准备中文名、英文名、缩写、常见别名、核心操作和问题模型。
   - 英文资料不能只用中文关键词检索。
   - 按来源清单中的正文格式先定位文件或章节，再搜索正文补漏；Markdown 与 LaTeX 使用各自的文件 glob。

3. 检查四个来源。
   - 每个来源都先确认目录是否可读。
   - 分别记录检索词、命中文件和判断结果。
   - 遵守来源清单中的特殊入口规则，尤其是 OI Beats 的旧目录回退和 Handbook 的 LaTeX 优先顺序。
   - 搜索命中不等于实际参考。只打开主题或问题模型直接相关的正文文件，不为凑数量采用弱相关材料。

4. 阅读并分类信息。
   - 按来源清单中的主要用途分工阅读，不把任一来源当作绝对权威。
   - 记录真正影响写作判断的文件；不要把所有搜索命中都列成参考。

5. 处理冲突。
   - 不设置绝对权威顺序。来源清单中的“主要用途”只决定优先核对方向，不自动决定结论。
   - 来源结论冲突时，通过独立推导、rbook 现有文章与代码、编译、固定用例或随机对拍决定采用方案。
   - 在研究记录和最终回复中说明冲突、采用方案和理由，不把冲突说明写进成品文章。

6. 独立校验。
   - 定义与公式要重新推导关键条件，不能因为多个来源写法相同就跳过验证。
   - 代码思路要结合 rbook 的接口、下标、输入输出和边界约定检查；适合运行时应编译和测试。
   - 无法验证的内容不要写成确定结论，并在记录中标记风险。

## 内容使用边界

四个资料源的许可证并不完全相同，具体声明见来源清单。为了让 rbook 文章保持独立表达并满足用户的来源隔离要求：

- 只借鉴知识组织、关键观察、讲解角度、问题分类、典型例子的功能和遗漏点。
- 不复制、近似改写或整段翻译原文，也不直接搬运来源代码。
- 结合独立推导和项目语境重新组织表达。
- 不在成品文章 Markdown 的 front matter、正文、注释或“参考”章节中写入资料库名称、文件路径、来源说明或致谢。
- `reference_record/` 中的本地研究记录是唯一允许写入详细来源信息的文章目录内 Markdown；它必须被 Git 和 rbook 页面索引忽略。
- 单独研究任务可以在回复中明确列出来源。只有用户明确要求引用短句时才做最小必要引用，并标明路径和引用范围。

## 研究记录

配合文章任务时，每次研究都创建独立文件：

```text
<文章目录>/reference_record/YYYY-MM-DD-HHmm-<topic>.md
```

- 时间使用本地时间，`<topic>` 使用简短、可识别的 kebab-case 英文名；无法确定时使用 `reference-research`。
- 同一分钟发生重名时追加 `-2`、`-3`，不要覆盖旧记录。
- 这个目录必须匹配仓库根 `.gitignore` 中的 `book/pages/**/reference_record/`，并由页面收集器显式排除。
- 单独研究且没有目标文章目录时默认不落盘；用户指定保存位置后再创建记录。

研究记录使用下面的结构：

```markdown
# 参考资料研究记录

- 时间：YYYY-MM-DD HH:mm
- 主题：<算法或问题模型>
- 目标文章：<绝对路径或“无”>

## 检索词

## OI Wiki

- 状态：已检索 / 路径不可用
- 命中与读取：<文件绝对路径及是否采用>
- 采用内容：<独立概括>
- 未采用内容：<文件或观点及原因>

## cp-algorithms

<同上>

## OI Beats

<同上；注明是否使用 docsOld>

## Competitive Programmer's Handbook

<同上；注明读取的 chapter 文件与章节范围>

## 冲突与取舍

## 独立校验

## 文章隔离检查
```

记录中也不要大段复制或翻译来源内容。记录检索事实、判断和验证证据即可。

## 最终回复

配合文章写作时，最终回复必须按资料源分组披露，且这份披露不能回写到成品文章：

- `OI Wiki`：逐个列出实际采用文件的绝对路径和具体用途；没有合适内容时说明已检索但未采用；不可用时列出失败路径。
- `cp-algorithms`：使用相同格式。
- `OI Beats`：使用相同格式，并说明是否因当前内容无匹配而检索了旧目录。
- `Competitive Programmer's Handbook`：使用相同格式；采用时列出具体 `chapter*.tex` 与用途，未采用时说明已检索但无直接内容。
- 另列研究记录文件的绝对路径。
- 有冲突时简要说明采用结论与验证依据。

单独研究任务使用相同分组，但研究结论、差异和验证结果是主要输出。没有文章目录时说明“本次未生成 reference_record”。

## 完成前检查

- 来源清单中的四个当前内容入口都已检索，或已记录不可用路径。
- 已遵守来源清单中的特殊入口规则。
- 只把真正影响判断的文件列为采用资料。
- 冲突已经独立验证，无法验证的风险已经标记。
- 没有复制、近似改写、整段翻译或直接搬运来源代码。
- 成品文章 Markdown 不含资料库名称、路径、来源说明或致谢。
- 有目标文章目录时已经生成独立研究记录，且没有覆盖旧文件。
- 最终回复按四个来源分组，并列出研究记录路径或说明未落盘。
